## 零、一句话

**7 个角色的行走图 + 7 张脸图**，合计约等于一张 576×384 的行走图表 + 一张 576×288 的脸图表。换算成像素量很小，难的是款式对不对。

---

## 一、硬规格（不合就切帧错位）

### 1.1 行走图

| 项 | 值 |
|---|---|
| 单帧 | **48×48 px** |
| 单个角色 | **3 列 × 4 行 = 144×192 px** |
| 一张表装 8 个角色 | **576×384 px**（角色按 4 列 × 2 行摆放） |
| 更省事的做法 | 一张图只放一个角色，文件名加 `$` 前缀，如 `$ChengMing.png`，尺寸 144×192 |
| 行 = 朝向 | **第 0 行朝下 / 第 1 行朝左 / 第 2 行朝右 / 第 3 行朝上** |
| 列 = 步态 | 第 0 列抬左脚 / 第 1 列站立 / 第 2 列抬右脚 |
| 底色 | **必须带 alpha 通道**，绝不能是纯色底 |

⚠️ **行顺序不能改。** 引擎写死 `characterPatternY = (direction - 2) / 2`，方向码 2/4/6/8 依次映射到第 0/1/2/3 行。上下颠倒是我第一版就踩的坑。

⚠️ **别给纯色底。** `$Frog.png` 原图是纯紫底，去背后我花了两轮才把边缘渗色修干净——Pillow 缩放 RGBA 时四通道独立插值，透明区残留的底色会渗进可见边缘。

### 1.2 脸图（对话框头像）

| 项 | 值 |
|---|---|
| 单张 | **144×144 px** |
| 一张表 8 张 | **576×288 px**（4 列 × 2 行） |
| 也可以 | 每张单独一个文件，命名与行走图对应 |

### 1.3 图块（可选，优先级最低）

RTP 实测尺寸：A1 768×576 · A2 768×576 · A3 768×384 · A4 768×720 · A5 384×768 · B/C/D/E 各 768×768。调色板 PNG 或 RGBA 都能吃。

## 二、角色清单（7 人）

### C1 · 成名 —— 主角，落魄书生

| 部位 | 明代形制 |
|---|---|
| 头 | **网巾**（明代成年男子束发的标志，细带束额） |
| 身 | **青布直裰**：交领右衽、大袖、两侧开衩、系带 |
| 腰 | **丝绦**（细绳带，可垂穗） |
| 足 | 布鞋或皂靴 |

**气质要求**：衣料旧、洗得发白、下摆可有一处补丁。用色沉闷（青灰、月白）。他要传达「被生活磨钝了」，不是「清贫而风雅」。

### C2 · 成妻 —— 务实，先提议自寻

| 部位 | 明代形制 |
|---|---|
| 身 | **交领短袄 + 马面裙**；外可加**比甲**（无袖长背心，明代妇女典型外衣） |
| 发 | **䯼髻**（发髻外罩网罩）或简洁圆髻，可插一支木簪 |

用色：褐、暗红、月白。

### C3 · 成子 —— 九岁，闯祸的那个孩子

| 部位 | 明代形制 |
|---|---|
| 身 | **短褐**（粗布短上衣）+ 长裤 |
| 发 | **总角 / 丱发**（头顶两个小髻），或剃发只留顶心一撮 |
| 足 | 草鞋或赤足 |

用色：土黄、灰蓝——与父母同色系但**更亮一点**，暗示他还没被生活压住。

### C4 · 驼背巫 —— 神卜老者，全篇最神秘的一段

| 部位 | 明代形制 |
|---|---|
| 身 | **道袍 / 氅衣**，宽大飘逸 |
| 头 | **斗笠** 或 **幞头** |
| 特征 | **脊背明显隆起**——这是他的辨识度所在，别画成普通老头；可拄杖 |

用色：土黄、灰褐、暗青。

### C5 · 里胥 —— 猾黠公差，玩家要恨他

| 部位 | 明代形制 |
|---|---|
| 身 | **皂隶短衫**（青黑），下穿**行縢 / 绑腿** |
| 头 | **皂隶帽**（方顶）或**方巾** |
| 关键道具 | 腰间**腰牌**——差役身份标志，请务必画上 |

**气质要求**：精瘦、略前倾、眉眼上挑。用色用全篇最暗的青黑与皂色。他是压迫感的来源。

### C6 · 村中少年 —— 养「蟹壳青」的好事者

| 部位 | 明代形制 |
|---|---|
| 身 | **短褐 + 罩甲**（无袖齐膝外褂），或对襟褂 |
| 头 | **网巾** 或 **六合一统帽**（瓜皮帽的前身） |

**用色要鲜亮**（宝蓝、绛红）——**刻意与主角的黯淡形成对比**，暗示他生活宽裕、有闲工夫斗虫。这个对比是叙事信息，不是配色偏好。

### C7 · 宰 —— 知县，结局落点

| 部位 | 明代形制 |
|---|---|
| 头 | **乌纱帽**，必须带两侧**展脚**翅——明代官帽的标志 |
| 身 | **圆领袍**（胸前可加**补子**）；明代七品知县服色为**青** |
| 腰 | **革带**（硬质宽带，明代官服特征） |

用色：青、绯。

## 五、怎么交给我

丢进这两个目录就行，文件名随你起：

```
assets/img/characters/    行走图
assets/img/faces/         脸图
```

构建脚本会把 `assets/` 整棵覆盖进工程，**事件数据与生成代码一行都不用改**——这条路已经被 `$Frog.png` 走通了。你给完之后我需要改的只有一处：角色清单里「行走图 / 索引」那两列。

⚠️ **一个请务必配合的点**：RTP 的立绘编号和行走图索引**对不上**。我实测 `pictures/People1_2.png` 是一张黄衣双马尾少女立绘，而行走图 `People1` 第 2 组是灰褐发灰衣形象——颜色和发型都不一致。

**所以：你给的行走图和脸图，请按同一顺序编号。** 否则我得靠肉眼逐个核对，那是 Day 2 本来要做的「素材对照页」干的活。

## 八、如果你找不到合适的明代素材

两条备选，都不需要你动手：

**A. 我来生成。** 用图像生成做单角色四向行走图，再用 `$Frog.png` 那套后处理切帧。**风险说清楚**：AI 出的四向行走图经常左右不分、四向不连贯，需要我逐帧修——大概率比找现成素材慢。

**B. 保持 RTP 现状。** 这不是凑合：MZ 的 Q 版小人本就高度抽象，观众对服饰的敏感度远低于写实画风。而且**「素材替换接口预留」本身就是管线成熟度的证据**——面试官看到「换整套角色只需替换 `assets/`，代码零改动」，比看到一张画得好的明代小人更有分量。
