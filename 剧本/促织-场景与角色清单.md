## 一、玩法定位（先定这个，再谈地图）

**类型：叙事驱动的探索游戏。不是 RPG。**

核心循环只有一个：

```
读旁白 → 与 NPC 对话 → 走到指定点交互 → 剧情推进
```

**明确不做**（写下来是为了防自己手痒）：

| 不做 | 理由 |
|---|---|
| 战斗系统 | 原文的斗虫是叙事高潮，不是数值对抗；`karminski/rpg-maker-agent` 正是卡在这里 |
| 等级 / 装备 / 商店 | 与故事无关，且一周围期做不完 |
| 随机遇敌 | 会破坏原文的线性压迫感 |
| 地图解谜 | 陷阱，容易吃掉两天 |

**唯一保留的「玩法」**：**按图索骥**。巫给的片纸是道具，在大佛阁后园使用它会给出方位提示。一个动作，撑起 P4 的探索感。

### C8 癞头蟆 —— 第一条非 RTP 素材

RTP 里**没有青蛙**（`Nature.png` 是狼/猫/猪/狐狸 + 精灵系，`!Other1.png` 是岩石球体宝石）。王翔提供了一张蛤蟆像素图，已转成 MZ 行走图：

| 项 | 值 |
|---|---|
| 文件 | `assets/img/characters/$Frog.png` |
| 规格 | 144×192（`$` 前缀单角色，3 列 × 4 行，每帧 48×48） |
| 转换工具 | `tools/make_frog_sprite.py` |
| 事件 | M3 `E11`，接触触发 → `SE: Frog`（指令码 **250**）→ 旁白 |

**这打破了「全 RTP」的约定，但是好事。** 它把「素材替换接口」从纸面变成了实证：外部素材只需丢进 `assets/`（目录结构与工程一致），构建脚本自动整棵覆盖进工程，**事件数据与生成代码一行都不用改**。Day 6 若要换掉整批 RTP 角色，走的是同一条路。

**技术上踩过的两个坑**：

1. 原图带纯色紫底且无 alpha 通道。去背后**必须把透明像素的 rgb 也一并清掉**——Pillow 缩放 RGBA 时四个通道独立插值，残留底色的 rgb 会渗进可见边缘，在蛤蟆右侧烧出一条紫边。修法是先把透明区 rgb 向邻近可见像素扩散填充，再缩放。
2. `$` 前缀的切帧公式与普通图**不同**：`宽/3、高/4`（普通图是 `宽/12、高/8`），且 `characterBlockX/Y` 恒为 0。尺寸不对就会切出半只蛤蟆。已用引擎源码逐条核对。

| 道具 | 作用 | 图标 | 实现状态 |

**不做背包系统**，不做物品栏 UI。道具只在剧情节点出现，用完即隐。MZ 默认的物品菜单够用，不改。

**竹筒铜丝笼不做。** 它若开局即在手，当门槛等于没门槛；不当门槛则只是一句文本提及。
P4 的捕虫动作已经由石穴那口「灌水」演完了，笼子在这条链上没有独立的位置。

### 实现记录（2026-09-24）

**「片纸」不做成菜单里可使用的道具，改为后园交互点触发。** 两条理由：

1. MZ 里能让道具「可使用」的 scope 只有 7–14（`Game_Action.isForFriend`），
   而这条路上 `determineItem` 必然弹出选人窗口（`showActorWindow`）——
   一人队伍里就是让玩家给「成名」用一下，多按一次确定，体验是坏的。
2. 剧本要的效果（「按图索骥」）本质是**认路**，不是「用道具」。
   原文也正是「执图诣寺后……蹲石鳞鳞，俨然类画」——
   图的作用是让你认出这就是画上的地方。落在交互点上，语义反而更准。

于是片纸走**关键物品**（`itypeId 2`）：进物品栏、看得见、有说明文案，
但不能在菜单里使用 —— 这正是 MZ 对关键物品的原生设计，不跟引擎较劲。

三件道具的图标都是**对着 IconSet 逐格核过**的。促织那两个共用 #2（绿团）——
MZ 全套 320 个图标里一个生物都没有（查过整张表，不是印象），这是权宜。
两件不会同时存在（青麻头在 P5 就被收走了），所以共图标不冲突。

### 事件词汇（数据层能力）

`lines` 里除台词外，可以放动作元组：

| 动作 | 引擎指令 | 说明 |
|---|---|---|
| `("给", 道具[, 个数])` | 126 | 获得 |
| `("收", 道具[, 个数])` | 126 | 失去（减到负数由引擎 clamp 到 0） |
| `("开", 开关)` | 121 | 打开全局开关 |
| `("声", 音频)` | 250 | 播 SE |
| `("乐", 音频)` | 249 | 播 ME —— BGM 会让位，播完自动接回来 |
| `("分支", 条件, 真段[, 假段])` | 111/411/412 | 真段/假段本身又是一串 lines，可嵌套 |

条件有两种：`("道具", 名称)`、`("开关", 名称)`。详见 `tools/game_data.py` 顶部注释。

**P3/P4 一个开关都不用，P5 却必须用 —— 这个转折值得记下来。**
那一段的状态全落在道具上（「问卜过」= 手上有片纸，「得虫过」= 手上有青麻头），
判道具即可。而 P5 的三件事（虫毙了、儿投井了、儿回来了）**不对应任何道具**：
虫毙了是东西没了，投井与复苏更是什么都没变。这时候才轮到开关。

四个开关（`失虫` / `投井` / `斗虫` / `献虫`）都是单向的一次性事实，开了不再关。
**变量不做**：本作一个数值都不用存。

### 音效实现（P5–P8）

剧本音频表里的 ME（Shock3 / Horror / Mystery / Victory1 / Shock1）**按 ME 实现**，
不是 SE：ME 会让正在播的 BGM 让位、播完自动接回来。这比切 BGM 干净 ——
不必记「原来放的是哪首」，也就不存在「忘了切回去」这种隐藏状态。
P5 那三个落在静默的 M1 上，听感与 SE 无异，但口径统一，将来给 M1 加 BGM 也不用改。

## 七、已知取舍（诚实交底）

三条都是**必须接受的既成事实**，不是待解决的问题：

**1. RTP 没有明代服饰。** `People1–4` 全部是现代/西式 Q 版卡通——看图确认过。结果就是「现代卡通村民演明代故事」。

这不是可以糊弄过去的细节，但也不是致命伤：MZ 的 Q 版小人本就高度抽象，观众对服饰的敏感度远低于写实画风。**而且它恰好是作品集的加分项**——「素材替换接口预留」正是管线成熟度的体现。若 Day 6–7 有余力，把 `img/characters/` 换成 AI 生成的古装行走图即可，**零代码改动**。

**2. 没有蟋蟀精灵。** 青蛙已由自制素材 `$Frog.png` 解决（见第三节 C8）。但**促织本身仍无精灵**——原文里它始终是「盆中之物」，靠文本与音效演出，这反而贴合原著的朦胧感。若 Day 6 要做，路径与 `$Frog.png` 完全相同。

**3. 立绘与行走图索引可能不对应。** 见第三节警告。Day 2 用对照页解决。

**意外的运气**：`!Other2.png` 里有墓碑、石雕像、火盆——M3 古陵场景的表现力比预期好；`audio/se/` 里有 `Frog` 与 `Chicken`——原文两个关键动作音效齐备；`img/pictures/` 有 40 张角色立绘——可做「视觉小说式」关键演出，这是计划外的资产。

## 八、备份方案（超时降级路径）

一周期期最怕中途崩掉，先把降级路径写死：

| 触发条件 | 降级动作 |
|---|---|
| Day 4 结束 M4 未完成 | M4 砍掉，P8 改为「旁白 + 立绘」演出，在 M2 内触发 |
| Day 4 结束 M3 未完成 | 斗虫场从 M2 空地移入 M3 门口，M3 缩为 17×13 |
| Day 5 结束仍有节拍未通 | 砍 P9 的「异史氏曰」与结局铺陈，用一屏旁白收尾 |
| 任意一天超时半天以上 | **立刻砍地图，不砍管线**。管线是作品集核心，地图是证据 |

最后一条是原则：**这场仗的重心是管线，不是游戏**。
